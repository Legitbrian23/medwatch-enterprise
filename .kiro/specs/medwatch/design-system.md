# MedWatch — Design System

> **Authority:** This document is the single source of truth for all visual decisions.
> It supersedes any conflicting visual guidance in `design.md` §6–§8 and in the v1 prompts.
> Database schema, API contracts, and test assertions in `design.md` §1–§5 are unchanged.

---

## 1. Governing Principles

| Principle | Detail |
|-----------|--------|
| **No icons** | Zero emoji, zero icon libraries, zero inline SVG pictograms. Navigation, buttons, tabs and cards are text-only. Status is communicated by text badges and semantic colour together. CSS-drawn shapes (dots, diamonds, squares) are permitted for map markers and chart marks only. |
| **Density-first** | Calm, precise, large tabular numerals. Information density preferred over whitespace padding. 8px grid. |
| **Tokens everywhere** | Every colour, spacing value, radius, shadow and chart colour is a CSS custom property. No hard-coded hex values inside components. |
| **Dual theme** | Dark (default, deep slate, not pure black) and light, driven by `prefers-color-scheme` with a manual override stored in `localStorage`. Dark theme is designed first; light is derived. |
| **Accessibility** | WCAG 2.1 AA contrast in both themes. Keyboard-navigable across all interactive surfaces. `prefers-reduced-motion` disables all animations. |

Allowed non-text graphics:

## 5. Spacing & Shape

- **Grid unit:** 8px (use multiples: 4, 8, 12, 16, 24, 32, 40, 48, 64)
- **Border radius:** `--radius-sm: 6px`, `--radius-md: 10px`, `--radius-lg: 14px`
- **Borders:** 1px solid `var(--border)` everywhere; no box-shadow on cards in dark theme
- **Elevation (light theme only):** `--shadow-sm: 0 1px 2px rgba(0,0,0,.05)`, `--shadow-md: 0 4px 12px rgba(0,0,0,.08)`

## 8. Component Standards

### 8.1 Status Badge

```
<span class="badge badge--critical">Critical</span>
<span class="badge badge--healthy">Healthy</span>
```

Text label only. Background from `--status-*-bg`, text from `--status-*`. No dot, no icon.

### 8.2 Delta Chip

```
+4.2 pts   (in --div-pos, prefix "+")
-6.1%      (in --div-neg, prefix "-")
```

Signed number + unit. No arrow glyph.

### 8.3 KPI Card

Structure: metric label (12px, muted) → hero value (36–48px, tabular) → signed delta chip → 12-point sparkline (ECharts micro-chart) → target progress bar → one-line auto-insight sentence → click-through link.

### 8.4 Data Table

- Sticky header, sortable columns (click header), resizable columns (drag divider), column visibility menu
- Sticky first column on wide tables
- Inline bar and sparkline in cells where relevant
- Row expansion drawer (replaces modal)
- Density toggle: Compact (32px rows) / Default (40px) / Relaxed (48px)
- CSV export button (text: "Export CSV")
- Virtualised rows via `@tanstack/react-virtual` for large datasets

### 8.5 Filter Bar

Shared component used by every list page: search field, select dropdowns (no custom icon widgets), date range, clear-all button. State synced to URL search params.

### 8.6 Drawer

Slides from the right (320px wide on desktop, full-width on mobile). Used for record detail views. Plain-language confirmation dialogs inside the drawer, not separate modals.

## 9. Chart Kit (Apache ECharts)

### 9.1 Setup

- Package: `echarts` (core) + `echarts-for-react` wrapper
- Register one theme object for `dark` and one for `light`, applied via `echartsInstance.setTheme()`
- Theme supplies: background transparent, font family Inter, axis line and tick in `--border`, grid lines at `--border-subtle` 0.4 opacity, tooltip background `--surface-3`, tooltip border `--border`, all chart colours from the categorical palette above
- All charts import only the ECharts modules they use (tree-shaking)

### 9.2 Standard Chart Props

Every chart component accepts:
```ts
interface BaseChartProps {
  data: unknown[];
  loading?: boolean;
  error?: Error | null;
  height?: number;
  theme?: 'dark' | 'light';
  compareData?: unknown[];        // dashed overlay
  onDrillDown?: (params) => void; // click handler
}
```

### 9.3 Required Features on Every Chart

- Crosshair tooltip with exact values, units, delta vs comparison period
- Synchronised crosshair with other charts in the same row (via `group` prop)
- Click-to-drill-down (district → facility → medicine) with breadcrumb update
- `dataZoom` brush on time-series charts
- Threshold and target lines
- Event annotations (e.g. "Delivery received")
- Table-view toggle (renders the underlying data as a `<DataTable>`)
- Skeleton state (matching chart height, animated shimmer)
- Empty state ("No stock records in this period")
- Error-with-retry state

## 10. Auto-Insights Engine

A pure TypeScript function `generateInsights(data, context): Insight[]` that returns plain-language sentences.

```ts
interface Insight {
  text: string;            // "Availability fell 6.2 points against August…"
  metric: string;          // linked metric name
  value: number;
  direction: 'up' | 'down' | 'neutral';
  severity: 'critical' | 'high' | 'medium' | 'low';
}
```

Rules:
- Pure function (no side effects, no API calls)
- Fully unit-tested in `apps/web/src/test/insights.test.ts`
- Sentence case, professional tone, no exclamation marks
- Every number has a unit and time context

Example outputs:
- "Availability fell 6.2 points against August, driven by Kotido and Arua."
- "Three facilities are projected to run out of Artemether-Lumefantrine within 30 days."
- "Stock-out days in Nakaseke decreased by 9 days compared with the previous period."

## 11. Dashboard Layout Template

Every dashboard page follows this structure:

```
[Page title + subtitle + scope]
[Key findings strip — 3 to 5 insight sentences]
[KPI row — 4 to 6 KpiCard components]
[Primary analytics row — one wide chart (2/3) + one supporting chart (1/3)]
[Secondary row — heatmap or ranking (1/2) + map or calendar (1/2)]
[Action list + DataTable]
```

Tabs within a dashboard: Overview | Trends | Facilities / Districts | Expiry | Supply chain
